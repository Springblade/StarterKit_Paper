# Preservation-package direction: adversarial literature check

Date: 16 November 2026. Research only; no agent trials, task qualification runs, application edits, or changes to the main-48 execution plan.

## Decision

**Accept with revisions as a bounded empirical extension; no demonstrated methodological novelty.** Making preservation-package access the primary intervention gives a more coherent practical question than a source-organization-by-package factorial. It does **not** establish stronger novelty: verification availability, brownfield feature work, and joint new/retained-behavior evaluation all have direct precedents. Its strongest prospective contribution is evidence about shipping a specific additional executable legacy-behavior package under otherwise identical agent capabilities, on two fixed starterkits. Calling the setting “SaaS” does not supply the missing contribution.

The candidate question is: *For these six feature tasks and a fixed agent/budget, does access to an additional runnable preservation-check package change the probability of delivering the requested feature while retaining specified existing behavior, and what does using it cost?* The proposed allocation is two repositories × three tasks × two V arms × four independent sessions = 48 attempts, native source organization fixed, one model, 900 seconds, no replacement attempts. This is a proposed design, not an experimental result.

Dropping S does not automatically increase V sample size: both the previous 2×2 arrangement and this proposal allocate 24 attempts per V level. A second repository changes the covered setting; two purposively selected repositories do not establish generalization to SaaS starterkits. The parent design/power audit owns formal inference and feasibility.

## Additional freshly verified threats and leads

**FeatureArc is a close outcome/mechanism precedent, outside the five-row shortlist because the list prioritizes interventions.** Yunlong Wang, Alyssa Wu, Cuiyun Gao, Jia Feng, Songyuanyi Lu, and Zhichao Hu, *FeatureArc: Benchmarking Coding Agents on Evolving Features*, arXiv:2610.37434v1 (2026). [Primary full text](https://arxiv.org/html/2610.37434v1), §§II.A–B, IV.B–D, V.C. Sequential requests operate on the agent's own earlier code in a continuing session. Hidden F2P/P2P stage and final chain gates are withheld; agents can run their own checks. The study links self-verification behavior to hidden outcomes. Therefore diagnosing green self-tests with failing held-out checks is not independently novel. Fresh-session package access differs from continuing uncorrected feature chains, but the proposed analysis must show concrete evidence beyond rediscovering unreliable self-tests.

**New November report found and traced to originals.** Shuai Wu, Yanna Feng, Yufang Li, Xue Li, Zhijun Wang, Bolun Liu, and Weilin Cai, *Patch correctness in automated program repair: A five-dimensional evidence framework and cross-benchmark audit from classical repair to coding agents*, arXiv:2611.10837v1 (7 November 2026). [Primary report](https://arxiv.org/html/2611.10837v1), §§2, 3.2–3.4, 5.1 and 7. This report introduces its own audit framework and synthesis, not a new randomized preservation-package trial. It explicitly distinguishes development-visible tests from final-assessment evidence, reproduction from regression preservation, and discrepancy from adjudicated incorrectness. Its golden-test observation cites Ahmed et al.; the primary empirical text was retrieved above. A generic “new audit framework” contribution is consequently weak; use concrete task-specific behavioral evidence instead. Numerical findings about other studies were not imported from this report.

**Not independently verified in this pass:** ExecCritic, IBM Issue-Test-Localizer, and the classical APR studies mentioned in the November report. Their existence as leads cannot establish method/results or novelty absence here. Their primary full texts were not attempted in this bounded pass, so they are **unverified**, not “unavailable.” All seven named full texts above were retrievable; Mehta's local HTML file is an old “No HTML” response, while the primary PDF is readable now. No paper is dismissed as inaccessible because that HTML conversion failed. Companion experimental artifacts were not rerun or exhaustively audited.

## Falsifiers and major risks

Applying the idea-evaluator's novelty discipline yields two major, presently fixable issues: **F1**, a setting substitution with no added knowledge over verification/testing precedents; **F6**, claims about independent correctness or broad effectiveness that the bounded design cannot verify. There is no experimental evidence here that refutes the proposed package effect; lack of results is not a negative result.

| Candidate claim | Evidence that would defeat or sharply narrow it | Consequence for the study |
|---|---|---|
| “This is a novel preservation method.” | Existing mechanisms above already provide regression checks or test context to coding systems. | Frame as a controlled empirical extension about a concrete delivery decision, unless a genuinely different package-construction method is specified and evaluated. |
| “The added package improves useful delivery.” | Joint new-feature-and-preservation outcome does not improve, or gains in preservation coincide with enough feature failures to erase joint benefit. | Report the complete outcome table and uncertainty, including unsuccessful attempts; do not select only completed patches. |
| “The package protects behavior beyond its visible examples.” | Visible checks pass while valid held-out public-path obligations fail; or the final score merely reruns the exact supplied assertions. | The latter measures the supplied contract only. Withheld, qualified checks can test additional sampled obligations, not all behavior. |
| “Runtime feedback caused improvement.” | Agent reads tests but never executes them, or executions produce no attributable behavioral observation. | Access can still act as documentation. Estimate availability as assigned; traces support descriptive uptake, not a causal mediation claim. |
| “The checks are actionable within 900 seconds.” | Dependencies, service setup, stale fixtures, or expensive suite execution consume the budget before feature work can be assessed. | Treat package usability and cost as part of the intervention; qualify execution without agent trials before commitment. |
| “This transfers across starterkits.” | Direction reverses between the two repositories, or all useful differences come from one task. | Report repository/task results transparently; two fixed kits cannot establish a population-wide transfer claim even if directions agree. |
| “Task qualification demonstrates actual benefit.” | Qualification only shows that authored bad variants are caught; observed agent faults are different or absent. | Keep constructed-fault sensitivity separate from prospective attempt success and detection of real saved-patch violations. |

If selection deliberately requires a plausible old-behavior fault missed by V0 and caught by V1, the experiment concerns that enriched workload. Such selection is legitimate when disclosed; it cannot estimate the average benefit across ordinary starterkit work. Avoid task-specific package content that discloses a new feature's implementation, privileged gold patch, or held-out acceptance solution.

## Incremental contribution candidates

1. **Primary candidate: an actionable package-access estimate.** Compare the same end-to-end feature requests under common tools, prompts, time budget, baseline repository state and final evaluator, with additional preservation-package availability as the assigned intervention. A useful contribution would be a bounded estimate of the resulting delivery/preservation/cost trade-off that the existing tool-ladder, test-localization, and staged-feedback studies do not directly estimate. A positive effect is not required for truthful reporting; an imprecise contrast is not evidence of equivalence.
2. **Supporting candidate: behavior-grounded validation artifacts.** Publish the specified old-behavior obligations, execution paths, assertions, admissible implementation alternatives, positive/reference checks and representative fault checks. This can make the estimate credible and reusable. These qualification practices are methodological rigor, not by themselves a novel testing framework.
3. **Supporting candidate: concrete failure boundary.** On retained final patches, distinguish package not used, check execution failed, observed failure not repaired, new feature unfinished, and independently observed legacy violation despite visible-check passage. Use saved logs and requirement-based adjudication. A count of “more tests ran” or generic false-green examples does not establish added research value.

The direct improvement dimension is **Stronger**, as a hypothesis about preserving specified behavior. **Higher** requires observed joint success; **Cheaper/Faster** could worsen because testing consumes a fixed budget. **Broader** is limited to adding a second fixed repository. No numerical skill score or paradigm-shift claim is justified from this literature review alone.

## Comparison with the S×V proposal

Preservation-primary is stronger in **question coherence and implementation tractability**, conditional on qualifying tasks and checks. It removes a source-layout intervention whose reach and behavioral parity must otherwise be established, and asks one deployable question. Its novelty case is **not automatically stronger**: S×V had a distinctive combination, while the new V-only mechanism lies closer to testing/verification precedents. A combination alone was also insufficient novelty.

The appropriate reason to prefer it is that a concrete, credible effect estimate about shipping additional legacy checks may be more useful than a diffuse factorial study with weakly realized layout differences. Replacing one repository's tasks with another's exchanges within-repository coverage for a small amount of external-setting evidence; it increases the observed repository contexts from one to two but does not double the number of agent attempts, guarantee power, or establish population generalization. Choose the new direction only if the six tasks create a real, independently assessable preservation decision and its eventual uncertainty is acceptable. No literature search can substitute for those local gates.

**Author checks still required:** exact external repository identity and suitability; task obligations and meaningful feature changes; V0/V1 content and exposure; common tool access; held-out evaluator independence and validity; repeatability within budget; no-replacement handling; and a contribution claim scaled to the realized precision. This file provides no authorization to execute trials.
